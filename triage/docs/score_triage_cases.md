# 转谱问题分诊病例库（RAG 知识库）

> **版本**: v0.2 | **更新日期**: 2026-10-22
> **面向对象**: Agent 检索、方案路由规则表、前端诊断卡片文案
> **文档性质**: 病例知识库（症状 → 根因 → 处方 → 验收 → 用户提示）
> **配套原型**: `diagnose.py` / `cases.json` / `router.py`（本仓库，可直接运行）
> **历史数据源**: `内部问题台账` §1.1–1.16（16 条特殊案例，含成功 / 失败 / 否决，见 §七）

---

## 一、这份文档解决什么问题

历史积累的特殊案例处置方法（固定范围切割、遮罩清除、逐页识别、多声部模式、DPI 调整等）此前只能靠人判断后再手动调用。本库把这些经验固化成**可检索、可匹配、可验收**的病例条目，使：

1. 同一类问题第二次出现时能被自动识别；
2. 前端能把"转码失败"翻译成"第几页、什么问题、建议怎么做"；
3. 未来接入 AI 时，本库直接作为检索语料（RAG）。

---

## 二、病例字段规范

| 字段 | 含义 | 要求 |
|------|------|------|
| 编号 | C01 起顺序编号，不复用 | 必填 |
| 名称 | 一句话问题描述 | 必填 |
| 分类 | 结构 / 版面 / 图像质量 / 识别缺失 / 识别分裂 / 识别身份 / 环境 / 语义 | 必填 |
| 严重级 | blocker（禁止交付）/ warning（可交付需复核）/ info（提示） | 必填 |
| 症状签名 | 可由脚本计算的指标 + 阈值 | 必填，不能写"看起来不对" |
| 根因 | 为什么会这样 | 必填 |
| 处方 | 自动 / 人工；具体动作 + 参数 | 必填 |
| 验收标准 | 修完用哪个指标判定变好 | 必填，禁止"人工看看"作为唯一标准 |
| 用户提示 | 前端直接显示的中文句子 | 必填，含页码/证据占位符 |
| 来源 | 首次出现的曲目、日期、样本位置 | 必填 |

**入库门槛**：每条病例必须有至少一份可回放的样本（原始 PDF 或逐页识别结果）。没有样本的条目只能标为"待验证"，不得进入自动处方。

## 三、病例清单

### 结构类

#### C01 合并结果结构非法（part-list 与 part 不对应）

- **严重级**: blocker
- **症状签名**: `merged.part_list_complete = false`，或 `part-list` 为空
- **根因**: 跨页合并把页内局部 `part.id` 当全局主键，跨页新声部未补登记 `score-part`；破坏性兜底清空 `part-list`
- **处方**: 自动 — 启用结构安全组装（声部并集 + 补登记），保留交付前校验
- **验收**: `part_list_complete = true` 且 `non_rest_notes > 0`
- **用户提示**: "这份谱的声部登记不完整，继续输出会得到空白谱面，已停止交付。请重试；若仍失败，请更换更清晰的扫描件。"
- **来源**: 2026-10-21某 9 页合唱谱（已修复）

#### C02 渲染结果为整页空白

- **严重级**: blocker
- **症状签名**: `render.blank_pages` 非空，或 `merged.non_rest_notes = 0`
- **根因**: 输出缺少乐器定义或无音符，MuseScore 判定无可渲染内容
- **处方**: 自动 — 禁止交付；回溯 C01 / C08；修复后重新渲染复验
- **验收**: 所有页墨迹占比 > 1%，且 `blank_pages` 为空
- **用户提示**: "转换结果没有生成有效谱面，已停止交付并保留诊断记录。请重试一次；仍失败请更换更清晰的扫描件。"
- **来源**: 2026-10-21同一合唱谱的旧合并结果（墨迹 0%）

#### C03 跨页声部结构不一致

- **严重级**: warning
- **症状签名**: `cross_page.structure_consistent = false`
- **根因**: Audiveris 逐页识别，不同页声部数量/名称天然不同
- **处方**: 自动 — 按声部并集组装；缺声部页补整小节休止；小节号全局对齐
- **验收**: 合并后每个声部小节数一致，`part-list` 与 `part` 一一对应
- **用户提示**: "各页识别出的声部结构不同，已按声部并集重新组装。若仍发现声部缺失，建议对异常页单独重转。"
- **来源**: 2026-10-21某合唱谱9 页（各页 Part 数 5/5/5/9/6/6/5/6/6）

### 识别类

#### C04 页内同名声部重复（识别分裂）

- **严重级**: warning
- **症状签名**: 某页出现两个及以上同名具体声部（如 S.×2、A.×2）
- **根因**: 同页上下两行谱被当成两套系统，各自生成一套 S/A/T/B
- **处方**: 人工 — 该页单独重识别（提高 DPI / 多声部模式）；仍重复则人工拆分或裁剪
- **验收**: 该页同名声部只保留一套，音符总数与原页一致
- **用户提示**: "第 {page} 页的声部被识别成了两套（同一名称出现两次），通常是两行谱被当成了两个系统。建议单独切出该页重转，或勾选'多声部'后再试。"
- **来源**: 2026-10-21某合唱谱第 4 页（9 个 Part，S/A/T/B 各重复）

#### C05 页内各声部小节数不一致

- **严重级**: warning
- **症状签名**: `page.measure_counts` 去重后长度 > 1
- **根因**: 某声部漏识别小节，或多识别出多余小节
- **处方**: 人工 — 该页重识别；对比相邻页小节数；必要时人工校正
- **验收**: 该页各声部小节数一致，或与相邻页连续
- **用户提示**: "第 {page} 页各声部的小节数不一致（{counts}），可能有声部漏识别或多了小节。请复核该页，或单独重转这一页。"
- **来源**: 2026-10-21某合唱谱第 9 页（7 / 8 小节）

#### C06 声部名称缺失或泛化（Voice / 空名）

- **严重级**: warning
- **症状签名**: 出现 Voice、空名、Unknown，或不同页命名体系混用（Voice vs S.）
- **根因**: Audiveris 未识别出声部标签，只能给通用名，跨页对齐不可靠
- **处方**: 人工 — 记录风险；合并层按顺序 + staff 对齐；提示人工复核声部顺序
- **验收**: 交付时声部顺序与谱面一致（人工确认，属于语义层）
- **用户提示**: "识别引擎没能识别出声部名称（显示为 Voice），跨页合并时声部可能对不齐。建议人工复核声部顺序，或对相关页单独重转。"
- **来源**: 2026-10-21某合唱谱第 1/3/5/6/7/8/9 页

#### C07 谱面声部标记多于识别声部

- **严重级**: warning
- **症状签名**: PDF 文本层检测到 S./A./T./B. 标记数 > 该页识别出的非钢琴声部数
- **根因**: 某声部在 OMR 阶段整页漏识别
- **处方**: 人工 — 该页重识别（多声部模式 / 提高 DPI）；仍缺失则人工补录
- **验收**: 识别声部数与谱面标记数一致
- **用户提示**: "第 {page} 页谱面上有 {labels} 个声部标记，但只识别出 {parts} 个声部，可能有声部漏识别。建议勾选'多声部'并单独重转该页。"
- **限制**: 仅对带文本层的 PDF 有效；扫描件（无文本层）依赖 Audiveris 的声部命名结果（与 C06 联动）
- **来源**: 2026-10-21某合唱谱第 4 页（某声部未独立识别）

#### C08 某页整页无音符

- **严重级**: blocker
- **症状签名**: `page.non_rest_notes = 0`
- **根因**: 该页 OMR 失败或图像质量过低（模糊、分辨率不足、谱线间距过小）
- **处方**: 人工 — 该页重识别（提高 DPI / 增强谱线）；仍失败则更换扫描件
- **验收**: 该页 `non_rest_notes > 0`，渲染墨迹 > 1%
- **用户提示**: "第 {page} 页没有识别出任何音符，常见原因是扫描件太模糊、分辨率过低或谱线间距过小。请更换更清晰的扫描页后重试。"
- **来源**: 历史案例（低质量扫描件）

### 环境与图像类

#### C09 OMR 引擎内存不足（JVM 1455 / OutOfMemory）

- **严重级**: blocker
- **症状签名**: OMR 日志出现 `errno=1455` / `OutOfMemoryError`
- **根因**: Windows JVM 内存提交耗尽，常见于整册一次性识别或并发过高
- **处方**: 自动 — 改用逐页识别并降低并发；必要时分批处理
- **验收**: 逐页识别全部成功，日志无内存错误
- **用户提示**: "识别引擎内存不足，通常是页数太多或同时处理的任务过多。请改用逐页识别、减少页数后重试。"
- **来源**: 2026-10-21 逐页识别报错（errno=1455）

#### C10 页面尺寸超限（>2000 万像素）

- **严重级**: warning
- **症状签名**: `pdf.pages[].pixels_at_dpi > 20000000`
- **根因**: 页面物理尺寸过大或渲染 DPI 过高，超过 Audiveris 硬上限
- **处方**: 自动 — 等比缩放到 2000 万像素以内，保持谱线间距约 20px
- **验收**: 缩放后像素数 < 2000 万，且识别成功
- **用户提示**: "第 {page} 页尺寸过大，已自动缩放。若识别仍失败，请提供更标准的 A4/A3 扫描件。"
- **来源**: Audiveris 技术边界（项目规则）

### 版面与语义类

#### C11 谱面含人声/伴奏声部（需要裁剪）

- **严重级**: info
- **症状签名**: PDF 文本层出现 S./A./T./B. 标记，且用户只需要钢琴部分
- **根因**: 合唱/伴奏总谱混排，人声声部干扰钢琴识别
- **处方**: 人工 — 按声部标签 Y 坐标固定范围水平切割，或白色矩形遮罩人声区域
- **验收**: 输出仅含钢琴声部，钢琴段落开头/结尾完整
- **用户提示**: "检测到这份谱包含人声声部。若只需要钢琴部分，建议开启'裁剪多余区域'后重新转换。"
- **来源**: 预处理规则 §2.2 固定范围水平切割

#### C12 识别语义问题（音高/节奏/声部错位）

- **严重级**: info
- **症状签名**: 确定性指标无法判定（无标准答案可比对）
- **根因**: 脚本只能验证结构，不能验证音乐正确性
- **处方**: 人工 — 前端收集用户反馈（空白/缺声部/错位/音符错乱/节奏不对），带诊断快照入库
- **验收**: 用户反馈与人工复核结论一致
- **用户提示**: "结构检查已通过。如果你发现音高、节奏或声部顺序不对，请点选下方的问题类型，我们会记录并跟进。"
- **来源**: 方案路由设计（2026-10-21）

## 四、前端诊断卡片契约

后端输出诊断 JSON，前端只负责呈现与回收，不做诊断。

```json
{
  "verdict": "blocked | needs_review | healthy",
  "findings": [
    {
      "case_id": "C04",
      "title": "页内同名声部重复（识别分裂）",
      "category": "识别分裂",
      "severity": "warning",
      "evidence": {"pages": [{"page": 4, "duplicate_names": ["A.", "B.", "S.", "T."]}]},
      "root_cause": "...",
      "prescription": {"mode": "manual", "action": "..."},
      "acceptance": "...",
      "user_message": "第 4 页的声部被识别成了两套……"
    }
  ]
}
```

**前端渲染边界**：卡片只呈现"页码 / 一句话问题 / 一句话后果 / 可用动作"四项；`case_id`、`evidence`、`root_cause`、`prescription`、`acceptance` 属于后端处置信息，只进诊断 JSON 与日志，不上屏。用户看不懂技术归因，看到只会困惑。

| verdict | 前端表现 | 用户可做的动作 |
|---------|---------|---------------|
| `blocked` | 红色卡片，禁止下载 | 重试 / 更换扫描件 / 单独重转异常页 |
| `needs_review` | 黄色卡片，允许下载 | 下载并复核 / 对指定页重转 |
| `healthy` | 绿色卡片 | 下载 + 反馈入口 |

**反馈入口**（对应 C12）：`[整页空白] [缺声部] [声部错位] [音符错乱] [节奏不对] [没问题]`。每次点击带上 PDF 指纹 + 诊断快照入库，作为新病例样本。

## 五、维护规则

1. **新案例先入库，再改代码**：新增处置逻辑前，先在本文档登记症状签名与验收标准。
2. **每条病例必须有样本**：样本路径写入"来源"，无样本不得标为可自动处置。
3. **禁止无签名条目**：不能写成"识别效果差"这类无法计算的描述。
4. **处方必须可回滚**：自动处方执行前保留原文件，执行后按验收标准复验，不达标回滚并升级人工。
5. **同一症状只保留一条病例**：发现语义重叠时合并改写，不追加副本。
6. **病例进入 `cases.json` 的前提是已实现对应 matcher**：仅登记、尚未实现检测的条目不进 `cases.json`（否则路由静默漏检），只留在 §七 历史台账并标"可脚本定位：是·未实现"。

## 六、当前覆盖与边界

| 类别 | 能否自动定位 | 能否自动处置 | 已登记病例 |
|------|-------------|-------------|-----------|
| 结构（合并/登记/对齐） | 能 | 能 | C01 / C02 / C03 |
| 识别分裂 / 缺失 | 能 | 部分（需单页重识别） | C04 / C05 / C07 / C08 |
| 识别身份（命名） | 能 | 不能，只能提示复核 | C06 |
| 环境 / 图像质量 | 能 | 能 | C09 / C10 |
| 版面（裁剪/遮罩） | 部分（需标签或文本层） | 能（参数需人工确认） | C11 |
| 语义（音高/节奏） | 不能 | 不能 | C12（靠用户反馈） |

**结论**：结构、环境、图像质量三类可做到全自动；识别类可定位、部分可处置；语义类只能靠用户反馈闭环。

**已知缺口（本轮记录，未修）**：H13 的"页内多 Part 是同一谱表的碎片"与 C03 的"跨页声部并集"在结构上无法靠 Part 数区分。当前实现只按"各页结构是否一致"决定是否折叠为单一钢琴 Part；若某页独有 3 个碎片 Part、其余页各 1 个，结构不一致 → 不折叠 → 输出 3 个 staff。该场景尚未有判定签名，遇到时只能人工比对谱面。
